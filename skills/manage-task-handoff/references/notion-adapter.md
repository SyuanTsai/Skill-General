# Optional Notion adapter

This is an example mapping for adopters who chose Notion. It does not make Notion the public template's authority. Establish the adopter's intended workspace, role, data source identities and write authorization before any live mutation. Existing memory and Handoff data sources are distinct; a missing AI Memory source does not prove the Handoff source is missing. Do not create properties, databases, or a migration as an implicit fallback.

The legacy `Context Handoffs` data source contains one older main per exact `Task Key` with Intent, Scope, Current, Source, Lifecycle, Work State, and optional Keep Active Until. `Context Handoff Changes` keeps field changes with Merged flags. If the user explicitly resumes that exact old key, read the one matching main and all its related unmerged changes, replay them according to [the legacy contract](legacy-notion-handoff-contract.json) and [read-only algorithm](legacy-notion-handoff-operations.md), and map the effective snapshot to a read-only legacy common view. Duplicates or invalid/colliding changes remain integrity errors. An opening conversation or a similar topic does not enumerate or reactivate those records. Do not rewrite the old tables or scan them for batch migration; they may naturally archive.

For new v1 records, the adopter must supply a separately verified physical mapping for scoped common, peer branch, recovery, and immutable event records. The mapping must bind the adopter-defined Authority Scope into physical identity and authorize every operation using the connector's trusted caller context plus an adopter policy; page IDs, Task Keys, Branch IDs, and page content do not authorize access. Notion page `last_edited_time` may advance on maintenance, so it is a valid Last Activity At only when the adapter can prove writes are material; otherwise use an explicit material-activity property. Notion's native last-edited metadata is not a storage compare-and-swap primitive by itself. If the connection cannot enforce authorization, expected revision, and idempotent Operation ID with an equivalent atomic mechanism, it cannot be used for concurrent v1 writes. Report unavailable durable writes instead of silently applying last-write-wins. Do not add a custom revision or Authority Scope property without a separately authorized, verified adapter design.
