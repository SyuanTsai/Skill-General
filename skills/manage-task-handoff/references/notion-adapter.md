# Optional Notion adapter

This is an example mapping for an opaque memory target whose trusted adopter configuration selects the Notion adapter. Choosing the target does not make Notion the public template's authority and does not require the core to know a provider, account, model, endpoint, or signer. Inspect this adapter's activation requirements only when that selected target is about to perform content I/O. Establish the adopter's intended workspace, role, data source identities and write authorization before any live mutation; missing or unverified activation fails closed before content access. Existing memory and Handoff data sources are distinct; a missing AI Memory source does not prove the Handoff source is missing. Do not inspect an unselected Notion adapter or create properties, databases, or a migration as an implicit fallback.

## Capability status

- Supported: an exact, authorized legacy read-only continuation is supported when trusted-principal resolution, an adopter-defined legacy scope mapping, and exact Task Key authorization are available. It returns a read-only legacy view after replaying the matching main and unmerged changes.
- Not demonstrated: this reference does not demonstrate a concurrent v1 live-write adapter. A generic Notion page update or `last_edited_time` is not a compare-and-swap (CAS) primitive and cannot substitute for expected-revision conditional mutation.
- New v1 writes, or a denied or unavailable legacy mapping, mean the durable save did not complete. State the concrete reason and do not fall back to another connector or last-write-wins behavior.

The legacy `Context Handoffs` data source contains one older main per exact `Task Key` with Intent, Scope, Current, Source, Lifecycle, Work State, and optional Keep Active Until. `Context Handoff Changes` keeps field changes with Merged flags. Before querying either source, resolve the principal from trusted connector/host context and require an adopter-defined legacy workspace or data-source scope mapping plus policy authorization for that exact Task Key and read action. A caller-supplied key and workspace-wide connector credentials do not authorize the read. If the old source cannot be mapped to an authorized legacy scope, fail closed without querying or exposing record content. After authorization, if the user explicitly resumes that exact old key, read the one matching main and all its related unmerged changes, replay them according to [the legacy contract](legacy-notion-handoff-contract.json) and [read-only algorithm](legacy-notion-handoff-operations.md), and map the effective snapshot to a read-only legacy common view. Duplicates or invalid/colliding changes remain integrity errors. An opening conversation or a similar topic does not enumerate or reactivate those records. Do not rewrite the old tables or scan them for batch migration; they may naturally archive.

For new v1 records, the adopter must supply a separately verified physical mapping for scoped common, peer branch, recovery, and immutable event records. The mapping must bind the adopter-defined Authority Scope into physical identity and authorize every operation using the connector's trusted caller context plus an adopter policy; page IDs, Task Keys, Branch IDs, and page content do not authorize access. Legacy authorization is also required before its data-source query, but it uses an adopter-defined legacy scope mapping rather than pretending old rows already contain v1 Authority Scope. Notion page `last_edited_time` may advance on maintenance, so it is a valid Last Activity At only when the adapter can prove writes are material; otherwise use an explicit material-activity property. Notion's native last-edited metadata is not a storage compare-and-swap primitive by itself. If the connection cannot enforce authorization, expected revision, and idempotent Operation ID with an equivalent atomic mechanism, it cannot be used for concurrent v1 writes. Report unavailable durable writes instead of silently applying last-write-wins. Do not add a custom revision or Authority Scope property without a separately authorized, verified adapter design.
