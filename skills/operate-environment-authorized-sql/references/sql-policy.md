# SQL enforcement requirements

The environment matrix is DEV SELECT/UPDATE/DELETE; UAT SELECT/UPDATE; PRD SELECT. All other operations, including INSERT, MERGE, DDL, EXEC/procedures and permission changes, are denied. Existing application-driven integration tests need their own explicit scope and cannot bypass this execution policy to insert test data.

The future service parses the complete T-SQL AST using Microsoft.SqlServer.TransactSql.ScriptDom, verifies one permitted statement and resolves every object/function/view dependency. Legal authorized SELECT/JOIN/CTE/aggregate and diagnostic queries remain supported. SELECT INTO, batches/GO or hidden statements, CTE writes, dynamic SQL, external/cross-database sources, unknown functions and unverified dependencies fail before execution. A leading SELECT, keyword filter, regular expression or read-only GUI toggle is insufficient. The offline contract checker deliberately does not parse SQL; a shape-valid malicious SELECT envelope still requires runtime rejection.

Object, column and row authorization must be enforced by the service even across aliases, joins, CTEs, aggregation and view dependencies. TOP/result limits are output controls, not row authorization. WHERE presence is not proof of a permitted write. The parser must not silently accept a syntax form whose scope cannot be proved. Recheck dependency/schema evidence after changes; deny affected operations until verified.

UPDATE/DELETE take only structured inputs. The service checks approved table/write columns, keys and expected values/rowversion; combines all predicates safely; executes the write and affected-row check in one transaction; and rolls back on concurrency or row-limit failure. COUNT before a later write cannot eliminate a race. Verify triggers, cascading effects and external/nontransactional side effects against the complete grant before enabling writes. Rollback cannot be assumed to undo external effects. Keep verified compensation/test-data restoration procedures for committed mutations; software rollback is not data rollback.

Use the actual authorized test database when checking immediate integration results; an asynchronously updated read replica is not an automatic substitute. DMV queries require the existing database principal's actual rights. Local Windows administration does not grant DB rights.

Microsoft's current [SqlClient Entra guidance](https://learn.microsoft.com/en-us/sql/connect/ado-net/sql/azure-active-directory-authentication?view=sql-server-ver17), [MSAL/WAM guidance](https://learn.microsoft.com/en-us/entra/msal/dotnet/acquiring-tokens/desktop-mobile/wam), [ScriptDom repository](https://github.com/microsoft/SqlScriptDOM) and [Windows service identities](https://learn.microsoft.com/en-us/windows/win32/services/service-user-accounts) are implementation references. No such executable dependency is bundled by this Skill. P3–P4 must independently verify current compatibility, company-approved clients, any required SqlClient Azure extension, and pin exact package versions with evidence when runtime implementation begins. No unverified runtime version is asserted here.
